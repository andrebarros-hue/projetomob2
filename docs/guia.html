Como conectar
o aplicativo ao mock

Passo a passo para entender o contrato, usar o mock que já vem no app e, quando o professor pedir, apontar o celular para um servidor HTTP de verdade.

Conta de demonstração: lia@ciclo.app · senha 123456
Contrato completo: docs/api.md

1. Abra o projeto certo

  1. Abra o Android Studio.
  2. Escolha Open e selecione a pasta ciclo, a que contém o arquivo pubspec.yaml. Não abra só a pasta android.
  3. Espere o Flutter terminar de baixar os pacotes. Se nada acontecer, abra o terminal do Android Studio nessa pasta e rode flutter pub get.
  4. Inicie um emulador ou conecte o celular e aperte Run.

A primeira tela pede e-mail e senha. Entre com lia@ciclo.app e 123456. A home abre com cinco hábitos de exemplo. Nada disso precisa de internet: o mock mora dentro do aplicativo.

2. As três peças

A tela nunca chama a rede direto. O caminho é sempre este:

  1. A tela pede um dado ao repositório (AuthRepository ou HabitRepository).
  2. O repositório monta o request do contrato e entrega a um transporte.
  3. O transporte devolve JSON. O repositório vira isso em UserProfile ou Habit. A tela só desenha.

Hoje o transporte é o MockTransport. Ele chama o CicloMockServer, que responde na memória como se o endereço fosse https://mock.ciclo.app/v1. Esse endereço é o nome do contrato. Não existe um site nesse host.

A escolha está numa linha de lib/main.dart:

runApp(CicloApp(services: AppServices.mock()));

AppServices.mock() cria o servidor, o transporte e os dois repositórios. As telas recebem AppServices e não sabem se a resposta veio da memória ou da rede. Por isso dá para trocar o mock sem reescrever a interface.

ArquivoO que ele faz
lib/main.dartLiga o app no mock embutido ou no HTTP.
lib/app/app_services.dartMonta repositórios e transporte.
lib/scenesTelas. Falam só com repositório e sessão.
packages/ciclo_core/lib/src/repositories.dartTraduz o contrato para objetos.
packages/ciclo_core/lib/src/transport.dartMock em memória e cliente HTTP.
packages/ciclo_core/lib/src/mock_server.dartRegras: login, validação, sequência.
mock/server.mjsO mesmo contrato, num processo Node.
docs/api.mdRequest, response e erro de cada rota.

3. Leia o contrato antes de mudar código

Abra docs/api.md com o projeto do lado. Cada rota tem o JSON que entra, o JSON que sai e o erro. O que a tela mostra de vermelho vem desse erro, não de um texto escrito na mão dentro do botão.

Formato de erro, em todas as rotas:

{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Revise os campos destacados.",
    "fields": { "password": "Informe a senha." }
  }
}

Rotas que a interface usa:

MétodoCaminhoPara quê
POST/auth/loginEntrar. Devolve token e usuário.
POST/auth/logoutEncerrar a sessão.
GET/habitsListar hábitos, meta do dia e usuário.
POST/habitsCriar. Resposta 201.
PATCH/habits/{id}Editar título, ícone, cor, frequência.
PATCH/habits/{id}/completionMarcar feito ou pendente.
DELETE/habits/{id}Remover.
POST/dev/resetSó no mock. Restaura os exemplos.
GET/healthDiz se o servidor HTTP está no ar.

Menos o login e o /health, toda rota exige o header Authorization: Bearer {token}. Sem ele a resposta é 401.

4. Acompanhe um login

  1. Abra lib/scenes/login/login_view.dart. O botão chama model.submit().
  2. O view model chama auth.signIn(email, password).
  3. RemoteAuthRepository manda este request:
POST /auth/login
Content-Type: application/json

{"email":"lia@ciclo.app","password":"123456"}

O mock responde 200:

{
  "token": "mock-token-usr_001",
  "user": {
    "id": "usr_001",
    "name": "Lia Martins",
    "email": "lia@ciclo.app",
    "initials": "LM",
    "completedCount": 18
  }
}

O app guarda token e usuário no SessionStore e abre a home. A home pede GET /habits com o header Authorization: Bearer mock-token-usr_001.

Erros que dá para ver sem debugger

  • Apague a senha e toque em entrar. O mock responde 422. O campo fica com a frase de error.fields.password.
  • Troque a senha da Lia para errada. O mock responde 401 com a mensagem “E-mail ou senha não conferem.”
  • Use outro e-mail, por exemplo ana@escola.com, e uma senha de pelo menos 4 caracteres. O mock cria a sessão.

5. Acompanhe um hábito concluído

O botão de check não soma a sequência na tela. Ele manda:

PATCH /habits/hab_002/completion
Authorization: Bearer mock-token-usr_001

{
  "completed": true,
  "completedAt": "2026-10-30T21:15:00-03:00"
}

A resposta traz o hábito inteiro, com streak novo, e o usuário com completedCount atualizado. A tela troca o card pelo objeto que voltou. Se amanhã o cálculo da sequência mudar, muda no mock, não em cada widget.

A sequência só cresce em dia previsto para aquele hábito. “Caminhar” é segunda, quarta e sexta. Numa terça o check ainda marca o dia, mas a conta de dias seguidos olha só os dias da frequência.

6. Suba o mock HTTP

O mock embutido basta para apresentar o app. O passo abaixo é o que conecta num endereço, como o contrato descreve.

  1. Instale o Node.js 18 ou mais novo, se o computador ainda não tiver.
  2. Abra um terminal na pasta ciclo.
  3. Rode node mock/server.mjs e deixe esse terminal aberto.
  4. A última linha diz que o mock escuta em http://localhost:4010/v1.
  5. Em outro terminal, prove: curl http://localhost:4010/v1/health. A resposta tem "status": "ok".

O arquivo mock/ciclo.http repete login, lista, conclusão e criação. No Android Studio dá para executar com o plugin HTTP Client. Para os testes automáticos do contrato: node --test mock/logic.test.mjs.

Toda vez que o servidor liga, as sessões zeram e os hábitos de exemplo voltam. É de propósito. Isso é mock de aula, não um banco.

7. Aponte o aplicativo para esse mock

  1. Pare o app no Android Studio.
  2. Abra lib/main.dart.
  3. Troque a linha do runApp por uma destas.

Emulador Android

Dentro do emulador, 10.0.2.2 é o seu computador.

runApp(CicloApp(
  services: AppServices.http("http://10.0.2.2:4010/v1"),
));

Simulador iOS, ou Chrome

runApp(CicloApp(
  services: AppServices.http("http://localhost:4010/v1"),
));

Celular físico

O celular e o computador precisam estar no mesmo Wi-Fi. Use o IP da máquina, o que o ipconfig ou o ifconfig mostrar.

runApp(CicloApp(
  services: AppServices.http("http://192.168.0.10:4010/v1"),
));
  1. Rode o app de novo.
  2. Abra a aba Perfil. O cartão Conexão deve mostrar HTTP http://... em vez de “Mock embutido”.
  3. Entre com lia@ciclo.app / 123456. Se a lista aparecer, a tela está falando com o servidor.

Nada nas telas muda. AppServices.http só troca o MockTransport pelo HttpTransport. Repositórios e widgets continuam iguais. O Android já aceita HTTP local (usesCleartextTraffic) e o iOS de desenvolvimento também.

8. Confira carregando, erro e vazio

  • Carregando. A home mostra o indicador enquanto GET /habits não volta. No mock HTTP o atraso fica visível.
  • Erro. No mock embutido, a aba Perfil tem “Simular falha do mock”. A próxima chamada responde 503 e a tela oferece “Tentar de novo”. No HTTP, pare o node e puxe a lista: a mensagem de rede aparece.
  • Vazio. Apague os hábitos. A lista explica o próximo passo. “Restaurar exemplos” chama POST /dev/reset.

A aba Sistema é o sample app do design system: cores, tipo, botões, campo, card, estado vazio e estado de erro. O tema está documentado em docs/design-system.md.

9. O que não fazer

  • Não coloque http.get dentro de um widget. A tela fala com o repositório.
  • Não mude um campo do JSON só na tela. Se mudar, mude juntos docs/api.md, CicloMockServer e mock/server.mjs.
  • Não esqueça o token no header. Sem ele o mock responde 401.
  • Não use https://mock.ciclo.app como endereço real. Quem responde é o código em memória ou o localhost:4010.

10. Se algo quebrar

SintomaO que olhar
Connection refusedO terminal do node mock/server.mjs está aberto? A porta é 4010?
Lista não carrega no emuladorUse 10.0.2.2, não localhost.
Celular não acha o computadorMesma rede Wi-Fi e o IP certo. Firewall pode bloquear a porta 4010.
Cleartext not permittedO manifest do projeto já libera HTTP. Confira se você não reverteu o AndroidManifest.xml.
401 em toda listaO login não aconteceu nesse servidor. Entre de novo depois de ligar o HTTP. Token de um processo não vale no outro.
422 ao criarTítulo vazio, ícone fora do catálogo ou frequência vazia. O campo vermelho diz qual.
flutter não é reconhecidoO plugin Flutter do Android Studio não está instalado, ou o SDK não está no PATH do terminal.

11. Checklist da entrega

  • flutter pub get terminou sem erro e o app abre.
  • Login da Lia mostra a home com hábitos.
  • Dá para concluir, criar, editar e apagar um hábito.
  • A aba Sistema mostra cores, tipo, botões, campo, card, vazio e erro.
  • docs/api.md e docs/design-system.md estão no projeto.
  • Você sabe apontar, em lib/main.dart, a linha que liga no mock.
  • Se for mostrar o HTTP ao vivo, o terminal do node mock/server.mjs fica aberto durante a apresentação.

O tema, as telas, o sample do design system e o contrato já estão no projeto. Conectar ao mock, no dia da banca, é trocar uma linha e deixar o servidor ligado.
